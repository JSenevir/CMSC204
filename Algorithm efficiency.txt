Algorithm efficiency measured by:
Time complexity & space complexity

always consider worst case scenario (talking about best case does not help)
same algorithm running on same system with same input will not produce exactly the same run over multiple runs (external factors)

growth rate: how time of the algorithm varies with the size of input data

assumption: an operation takes one unit of time

example: bubble sort
comparison is 1 unit
swap is 3 units
one pass contains comparison + swaps units
each pass reduces number of comparisons by one
forms quadratic equation
quadratic growth rate: O(n^2)

traversing an array: O(n) -- linear growth
example: for loops

nested loop is O(n^2). deeper nested iterations will result in O(n^3), O(n^4)... polynomial

accessing an element: O(1) -- constant time
does not matter how many elements are in the array
*if it takes the same number of steps regardless of growth of data

exponential: O(2^n) growth will double with each additional element in the input data set
Will quickly become very large
ex: Fibonacci recursive algorithm

critical section of algorithm: part of code that dominates time complexity calculation
example: the execution of a loop n times (not the loop part itself, the conditional i<n determines body executes n times)
for nested loops: the inner loop body is what executes the most times

O(logn) is the smallest after O(1)

rules:
- drop the lower order terms including constants
T = 2n^2 + 3n + 1
 remove 3n and 1
- drop constant multipliers
remove 2
T= n^2
n is the input size, if n is very large, 3n and 1 do not matter much
